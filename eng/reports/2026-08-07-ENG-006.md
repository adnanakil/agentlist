## What happened

`verify_prod.py` was failing the "both hero-CTA arms served" check even though production was splitting correctly. ENG-004 (2026-08-07) added `<div class="cta-preview"><span class="sms-bubble">` inside the `#herocta` block above the button. The old arm detector split HTML on `id="herocta"` then grabbed the first `<span>` inside the first `</div>` — but `</div>` now closes `cta-preview` first, so the captured span was the SMS preview text, not an arm label. The `arms` set came back empty every time.

## Change made

**`eng/scripts/verify_prod.py`**

- Added `import re`.
- Replaced span-scraping arm detection with `re.search(r'<body[^>]*\bdata-variant="([^"]+)"', html)`.
  `data-variant` is emitted on `<body>` by `routes/landing.py` (lines 185–187) and is the same attribute the tap beacon reads — stable and purpose-built for this.

No other files touched. No migration. No Railway deploy (this is a local script).
