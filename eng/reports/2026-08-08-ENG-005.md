## What was done

Added Meta Graph API (v21.0) integration to two growth scripts.

### budget_guard.py

- Reads `META_ACCESS_TOKEN` from env. Missing/empty → prints "Meta spend UNKNOWN — cap cannot be verified" and exits 1. Never shows Google-only totals as if they were complete.
- Fetches `act_40885463/campaigns` (ACTIVE filter, effective_status). Auth via `Authorization: Bearer` header — token never appears in URLs or logs. TLS via `certifi.where()` (Homebrew python3 has no CA bundle).
- Separates campaigns: daily-budget vs lifetime-budget.
- Daily-budget campaigns: worst-case projection = declared budget × 1.25 (Meta overdelivers up to ~125% on any given day; $12/day Messenger campaign spent $15.27 on 2026-08-07).
- Lifetime-budget campaigns: no daily cap to project — fetches 7d trailing actual avg via insights, prints informational only. Does not contribute to cap total.
- Combined cap: `total = google_total + meta_daily_projected`. When over cap, Google budgets scaled. Meta budgets not touched (growth's lane). Prints "Meta budgets unchanged (growth's lane)."
- Meta section runs before Google: if Meta is unknown, exits before touching Google at all.

### metrics.py

- Added `meta_spend(token, days)`: calls account-level insights with `time_increment=1`, returns `{date_str: spend_usd}`. Degrades gracefully on error (returns `{}`).
- `ad_spend()` now merges Google + Meta into unified by-day dict with `meta_cost_usd` field.
- Scoreboard table: new `meta spend` column. `window_spend` = Google + Meta (feeds naive CPA).
- JSON: adds `window_google_spend_usd`, `window_meta_spend_usd`; per-day entries include `meta_cost_usd`.

### tests/test_meta_spend_guard.py (new)

13 source-code-assertion tests verifying: token is read from env, exit(1) on missing token, Bearer header used (access_token= never in URLs), 1.25× multiplier, lifetime tracking, certifi, meta_spend() function exists, meta spend column, graceful degradation.
