## Problem

Both hero trust badges rendered as `✓<garbage>a0Your number is never sold` on texthal.com.

Root cause: `landing.py` line 559 contained `content:"✓\00a0"` inside a Python string literal.
Python's `\0` is an octal escape, so `\00a0` = chr(0) + the literal characters "a0" — a NULL byte
in the served CSS. Browsers render chr(0) as U+FFFD (`<garbage>`) followed by "a0", breaking the
copy on the highest-trust element on the page.

---

## What was built

**`services/hal-orchestrator/hal_orchestrator/routes/landing.py` line 559:**
```
-  .trust-badge::before {{ content:"✓\00a0"; color:var(--green-bright); }}
+  .trust-badge::before {{ content:"✓\u00a0"; color:var(--green-bright); }}
```
`\u00a0` is Python's Unicode escape for U+00A0 (non-breaking space). Renders as `e2 9c 93 c2 a0`
in UTF-8 — no NULL byte.

**Sweep**: Grepped entire `landing.py` for `\0`. Only one occurrence found and fixed.

**`services/hal-orchestrator/tests_onboarding_parent.py` — new section 8h (4 assertions):**

- `trust-badge::before` selector still present (no accidental removal)
- Both badge texts visible in rendered output
