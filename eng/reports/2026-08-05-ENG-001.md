## What Was Built

`eng/scripts/device_traffic.py` — a re-runnable script that:
- Fetches `hal_page_hits` and `hal_funnel_events` from the live Railway database (URL fetched via `railway variables`, never stored)
- Classifies user agents as mobile / tablet / desktop (tablet-first to handle iPads that carry "Mobile" in their UA)
- Joins taps to hits within the same UTC day (visitor_hash is day-salted)
- Reports device-class split overall and for `utm_source=google`, plus sms_tap rates per class
- Emits a recommendation with built-in thresholds: BUILD / DROP / MONITOR / INCONCLUSIVE

Builder: general-purpose Claude subagent (Kimi/Codex CLIs not available on Hal Mac; same substitution growth uses per runbook).

## Finding

**INCONCLUSIVE on the specific paid-traffic desktop question.**

The campaign was paused on 2026-08-05 (growth cycle 4) before enough paid hits accumulated in `hal_page_hits`. Only 2 `utm_source=google` rows are recorded (both classified as mobile). That sample is too small to measure a desktop share or compare conversion rates.

**Notable secondary finding**: 59% of ALL landing traffic (1,324 hits, organic + direct + paid) is desktop. This is a meaningful signal — more than half of everyone who hits the landing page is on a device where `sms:` links may be inert (Windows/Linux) or require opening the Messages app (macOS).

With 0 real sms_taps across all 1,324 visits from any device, there is no tap-rate delta to compare. The theory cannot be confirmed or refuted yet.

## Recommendation

**Do not build the QR-code desktop path yet.** Wait for:
1. EXP-006 deployed (hero CTA — in working directory, reviewed, awaiting Adnan)
2. Campaign re-enabled
3. 50+ paid clicks accumulated in `hal_page_hits`

Then re-run `python3 eng/scripts/device_traffic.py`. The script's recommendation logic will surface BUILD / DROP / MONITOR automatically based on the thresholds:
- BUILD if paid desktop ≥ 15% AND desktop tap rate < 50% of mobile rate
- DROP if paid desktop < 5%
- MONITOR otherwise

The 59% overall desktop share is high enough that the BUILD path is plausible once data arrives.
