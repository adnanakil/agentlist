# ENG-003 — Fix metrics.py: exclude verify-test events from SMS tap count

## Summary

Two SQL queries in `growth/scripts/metrics.py` were missing a `utm_source` filter, causing engineer smoke-test events (`utm_source='verify-test'`) to count as real user activity. This caused the growth team to read EXP-006's gate as "0.91% tap rate" when the real user tap rate was 0%.

---

## Changes

**`growth/scripts/metrics.py`** — two queries patched:

### hal_funnel_events (sms_tap count) — before
```sql
SELECT COUNT(*) FROM hal_funnel_events
WHERE event_type = 'sms_tap'
  AND created_at > now() - make_interval(days => $1)
```

### hal_funnel_events (sms_tap count) — after
```sql
SELECT COUNT(*) FROM hal_funnel_events
WHERE event_type = 'sms_tap'
  AND (utm_source IS NULL OR utm_source != 'verify-test')
  AND created_at > now() - make_interval(days => $1)
```

### hal_page_hits (landing views) — before
```sql
SELECT date(created_at) AS day, COUNT(*) AS n FROM hal_page_hits
WHERE path = '/' AND NOT is_bot
  AND created_at > now() - make_interval(days => $1)
GROUP BY 1 ORDER BY 1
```

### hal_page_hits (landing views) — after
```sql
SELECT date(created_at) AS day, COUNT(*) AS n FROM hal_page_hits
WHERE path = '/' AND NOT is_bot
  AND (utm_source IS NULL OR utm_source != 'verify-test')
  AND created_at > now() - make_interval(days => $1)
GROUP BY 1 ORDER BY 1
```

**Why `IS NULL OR`**: bare `!= 'verify-test'` in SQL evaluates to NULL for NULL-source rows (three-valued logic), silently dropping organic events. The `IS NULL OR` pattern keeps organic rows and excludes only smoke-test ones. The reviewer (general-purpose Claude subagent, substituting for kimi:kimi-review on the Hal Mac) caught this on the first review pass.
