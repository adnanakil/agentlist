## Summary

This is a diagnostic ticket requested by growth after EXP-006 (hero CTA) closed
as LOSS with a reported 0.91% tap rate (5 taps / 551 views). Eng investigated:
(1) the SMS CTA UX, (2) `/tap` event firing, (3) the post-tap SMS flow, and
(4) device/OS-specific failures.

**The most important finding is not about UX — it's about the data:** the "5 taps"
did not happen. Every `sms_tap` event in `hal_funnel_events` is a verify-test
smoke test. The real tap count is **0**. Growth's `metrics.py` has a missing filter.

Missing: `AND utm_source != 'verify-test'`. The `device_traffic.py` eng script
does filter them — that's why it showed 0. Growth's script does not.

**Actual tap rate across the full available window: 0 / 1,743 non-bot landing
views = 0%.**

## Findings (per acceptance criteria)

### 1. SMS CTA on mobile

Three CTAs exist on the landing page:
- **Hero CTA** (`id="herocta"`): mint pill on dark-green hero; shows "Text HAL ↗"
  (variant a) or "Text (646) 513-1421 ↗" (variant b). Visible above fold on wide
  screens; hidden when the sticky bar is present and the hero is on screen.
- **Sticky bar** (`id="stickycta"`): fixed to bottom on screens ≤820px. Same copy
  as hero. Shown by CSS (fail-open), hidden by JS IntersectionObserver while hero CTA
  is in the viewport.
- **Closing CTA**: smaller pill + number hint, always visible, copy-to-clipboard on desktop.

UX issues (code analysis — no physical device available):

| Issue | Detail |
|-------|--------|
| ↗ icon reads as "external link" | Diagonal arrow is conventionally "go to webpage"; visitors don't expect their SMS app to open |
| Variant A opaque | "Text HAL" — first-time visitors don't know HAL; no phone number visible |
| Pre-filled message invisible | Visitor never sees "Hi HAL — new baby here 👶 …" before tapping; the two-step action (tap → SMS app opens → press Send) is not explained |
| Desktop dead end | 61% of all traffic (32% of paid) is desktop where `sms:` is inert on Windows/Linux |

### 2. `/tap` event firing

Working correctly. The JS beacon fires with `keepalive: true` before the SMS app
opens. Dedup (60-second window), variant attribution, attribution code parsing, and
UTM passthrough all function. The endpoint infrastructure is not the problem.

No real taps to attribute — not a firing bug.

### 3. Post-tap SMS flow

When the pre-filled message is sent ("Hi HAL — new baby here 👶 What can you do?"):
- `detect_onboarding_track()` matches `_PARENT_PREFILL_RX` in `prompts/system.py`
- Sets track=parent, extracts and strips attribution code suffix, records `acquisition_source`
- HAL replies with a warm welcome and 3-step onboarding (name → baby name → city)
- Ask-caps prevent infinite re-asking of fields a user won't answer

The post-tap experience is well-designed. The friction is pre-tap, not post-tap.

### 4. Device/OS failures

None found. Android separator (`?body=`) vs iOS (`&body=`) is working (commit `f031001`).
No routing errors in the funnel data. The 0% tap rate is uniform — it's not a
device-class bug.

## Most Likely Friction Point

**Visitors don't understand what the tap will do.**

The button says "Text HAL ↗" but offers no preview of the SMS that will be sent or
any indication that tapping opens a native messaging app requiring a second action
(pressing Send). A visitor who taps, sees the Messages/SMS app open unexpectedly,
may close it without sending.

Secondary: 61% of all landing visitors are on desktop where the action is literally
impossible (Windows/Linux) or requires extra steps (macOS Messages).

---

## Blocking Issue: metrics.py bug

Growth's tap metrics have been wrong since EXP-001. Every gate read that used
`window_sms_taps` from `metrics.py` was counting verify-test events as real users.
This includes the EXP-006 read that triggered this ticket.

**Fix**: add `AND utm_source != 'verify-test'` to the query at `growth/scripts/metrics.py:77`.
This is a one-line change. Growth should fix it in their next cycle, or file ENG-003.

Until this is fixed, all tap-rate gates are unreliable.

---

## Proposed Hypotheses for Growth (EXP-011)

*Findings only, not implementations — per ticket instructions.*

1. Show a speech-bubble preview of the pre-filled message text above the CTA, so
   the visitor knows what they'll be sending before they tap.
2. Replace the ↗ arrow with a chat/phone icon to signal "this opens messaging."
3. Add CTA microcopy: "Opens your Messages app · one text to start."
4. Fix metrics.py first so the new tap-rate gate is accurate.
