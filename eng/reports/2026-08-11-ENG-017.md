## Summary

Fixed two bugs in `growth/scripts/metrics.py` that were making the growth
scoreboard materially wrong:

1. Landing-view counts were 10x+ inflated by verify/monitoring UAs that pass
   `is_bot=False`. The scoreboard showed 5,194 views last 14d; the real number
   is ~450. This corrupted every derived rate — most critically, SMS tap rate
   read 0.17% instead of ~2–3.5%, blocking the Reddit gate (Adnan decision D4:
   "hold until 2% tap rate").

2. Meta ad spend was always $0.00 because `META_ACCESS_TOKEN` wasn't loaded
   when metrics.py runs outside the supervisor context (e.g. manual invocation
   or eng cycle). True 14d spend is Google ~$103 + Meta ~$48 → CPA ≈ $16.9,
   not $11.49 as shown.

## Changes

### `growth/scripts/metrics.py`

**Added constants (module level):**
```python
_PROBE_UA_EXACT = (
    "Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) Version/17.0 Mobile Safari",
    "Mozilla/5.0 (Linux; Android 14; Pixel 8) AppleWebKit/537.36 Chrome/120 Mobile",
)
_PROBE_UA_ILIKE = ("%Verify/%", "%facebookexternalhit%", "%eng-verify-bot%")
```

Future monitoring probes are added in one place (constants) and automatically
picked up by the SQL clause.

**Added `_load_growth_env()` helper:**
- Reads `~/.growth-env` if `META_ACCESS_TOKEN` is not already in env
- No-op when supervisor already sourced the file
- Called at top of `main()` and `ad_spend()` (belt-and-suspenders)

**Updated `view_rows` SQL:**
- Builds PostgreSQL dollar-quoted exclusion clause from the constants
- `AND (user_agent IS NULL OR NOT (...))` preserves null-UA rows
- `sms_tap` event_type filter left untouched (per ticket requirement)

### `tests/test_metrics_tap_filter.py`

Added 4 new regression tests (ENG-017 section):
- `test_probe_ua_exact_contains_verify_prod_uas` — UA_IOS and UA_ANDROID in constant
- `test_probe_ua_ilike_contains_required_patterns` — Verify/, facebookexternalhit, eng-verify-bot
- `test_view_rows_query_excludes_probe_uas` — exclusion clause present in source
- `test_load_growth_env_called_before_ad_spend` — ordering verified in both `ad_spend()` and `main()`
